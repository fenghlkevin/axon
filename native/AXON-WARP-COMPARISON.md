# Axon 与 Warp 完整能力对比

基准日期：2026-10-09。Axon 基准为当前 native 源码；原始核对版本为 0.19.1（166），0.19.2（167）增量见下文；Warp 基准为当前官方公开文档。本文比较能力与实现边界，不代表同机、同模型、同任务的性能测试。已安装版本与当前运行进程版本可能不同。

Axon 已具备逐步决策、终端执行、真实结果反馈、审批、相关文件读取、修改预览与恢复日志。差距仍分布在项目理解、运行中协作、计划、开发工具、模型扩展、并发、云端及成熟度，不能概括为只剩命令展示，也不能用功能数量换算“完成百分比”。

## 状态与范围

- **基础已有**：对应机制已实现，仍须按场景验收，不能据此宣称与 Warp 同等可靠。
- **部分**：有相近机制，但关键范围或工作流不完整。
- **缺少**：当前 Axon 未实现对应产品能力。
- **保留差异**：用户明确选择保留，不作为待补功能。
- **待验证**：需要真实环境或同任务对照，无法从功能代码判断。

编号固定。后续版本逐项更新状态与验收结果。覆盖公开能力类别及与当前需求相关的子能力；不承诺覆盖 Warp 未公开实现、所有设置开关及未来新增功能。Memory 为 Research Preview，Factories 为 Early Access，不与常规本地功能混算。

0.19.15（180）的入口在 SFTP 工作台的本地文件「操作 → 开发工具…」。AI 修改仍从原审批的「查看差异」进入；文件列表中的 `.backup-UUID` 备份可从上下文菜单预览和恢复。手改/取消差异不会绕过权限、原文件检查、备份和目标验收；评论要求修订时不提交文件。超过 1,000 行的文件审查退为整文件一块，敏感预览遮盖并禁用该块手改，默认内容仍保持真实字节。

ED06 的整组暂存与故障恢复适用于既有文件端点，但逐个 rename 之间其他读者仍可能看到中间状态，进程崩溃、断电和持续断连无法保证自动恢复；日志与备份用于人工核对，不把它称为文件系统事务或完整原子提交。恢复拒绝覆盖提交后的人工作品，并明确报告哪些备份需检查。远端传输失败注入已检查，真实 SSH/SFTP 故障仍需环境验收。

Git 面板仅本机，命令使用独立 argv，并禁用 hooks、fsmonitor、外部 diff/textconv 与递归子模块。分支切换拒绝未处理修改和覆盖忽略文件；工作树移除只允许本应用登记、未锁定且无修改/无忽略文件的 checkout，保留分支。没有 commit/push/merge/rebase 面板或远端 Git 管理。项目任务按工作树目录保留历史，同一 checkout 共享一个活动实例；目录身份变更拒绝执行，沿用当前 AI 权限和检查，关闭项目任务停止其代理。隔离指目录/上下文/历史及不写 PTY，不代表操作系统沙箱，也不是云端或后台多代理调度。

语言服务遵循 [LSP 协议](https://microsoft.github.io/language-server-protocol/specifications/specification-current)，使用本机显式选择的 stdio 可执行程序及 JSON 字符串参数；不自动安装服务器，不支持远端 LSP。只接受 UTF-16 位置，拒绝越界/重叠编辑、过期格式化及异文件/过期版本诊断；不执行服务器请求的 workspace edits 或命令。格式化只修改草稿，保存检查原文件及字节、保留备份。没有代码补全、跨文件跳转/重命名、调试器或全部 LSP 扩展；诊断是否完整取决于服务器及项目配置。

## 6. 失败、恢复与完成验收

Warp 的公开文档说明代理持续执行及交接能力，但不足以证明所有部分执行场景均能自动恢复。以下对 Axon 的结论以自身实现为准，不推断 Warp 内部具有事务或 exactly-once 保证。

Axon 依据：`AITaskRecovery.swift`、`AITaskRecoveryViews.swift`、`AIFileTimeline.swift`、`AITaskMemory.swift`、`AIVerification.swift`、`AIAssistant.swift`、`VERIFICATION.md`。

| 编号 | 能力 | Axon 当前情况 | 状态 |

最近交付记录中，广泛测试出现一个真实 PTY 就绪测试的 5 个断言失败，隔离重跑通过。这支持“存在时序稳定性待查”，不支持“已与 Warp 同等可靠”。模型回复格式错误、重复观察和验收不一致仍是 P0 问题，不能靠增加工具数量替代修复。

0.19.16（181）在 AI 工作台增加「恢复证据」与「文件历史」。时间线针对 Axon AI 文件动作，保存未脱敏的原/新字节于本机私有目录（0700）及文件（0600），不会将快照正文自动作为模型上下文。最多 64 次修改、每次 8 个文件、每文件 64 KiB、总计 16 MiB；超过限额优先淘汰已核对记录，未核对记录不自动丢弃，无法保存则拒绝新写入。旧会话及 Shell、外部编辑器、手动文件编辑的修改不会补录。

ED11 的目标是对齐 [Warp 代码审查](https://docs.warp.dev/code/code-review/) 中按块撤销及整组丢弃的体验，并提供 Axon 自身的持久时间线；不是声明 Warp 内部使用相同快照方案。选择版本与文件后，预览撤销或重做，再勾选差异块并应用；只接受当前字节为该目标/目录某个已记录版本的文件，拒绝覆盖其他新内容。恢复本身成为新记录并保留备份，可再次撤销；单文件与组文件使用同一暂存、提交、失败恢复链路。完成回执不等于服务恢复，文件恢复会将关联任务标为中断并使验收失效。

恢复核对区分原版本、修改后版本、其他已记录版本、并发冲突及不可用。只有整组原字节重新核对后才将未确认的文件动作标为未应用，允许继续时重新提案和批准；整组新字节则标为已完成且不重放。混合状态需要人工选择补齐/撤销；恢复也重查当前策略与文件。单文件也沿用组提交链路，在最终 rename 前重新核对策略。对于任意 Shell 副作用、已丢失/删除文件、创建/删除/改名、崩溃后原名缺失、备份损坏和持续不可达情况，仍暂停并要求人工检查，不自动猜测或覆盖。跨文件可见性、跨程序竞态和持续断线不具有通用原子事务或 exactly-once 保证。

本机兼容验收矩阵见 [VERIFICATION.md](VERIFICATION.md) 的 0.19.16 节；覆盖 Bash/Zsh 的成功/非零退出、存活执行 ID 恢复、仅写入一次、未知 ID 拒绝和人工中断，并复验 Python/SQLite、长程序接管及过期 hook 证据拒绝。真实 SSH、不同远端系统、进程重启后的 PTY 再附着、fish/PowerShell 和与 Warp 同任务比较不在本轮通过范围。

## 开发优先级与完成标准

**P0：可靠完成现有任务。** 对应 EX03–04、EX08、RC04–08、QA01–06。固定创建脚本并运行、追加文件、服务查询、长命令、审批拒绝、断线和人工输入等用例。验收必须同时核对命令、目录、输出、退出码、文件结果及副作用次数；不允许“已完成却报告未执行”，也不允许缺证据就宣称成功。重复观察必须有上限和明确阻碍。

**P1：完成本地交互闭环。** 对应 CT02–09、CV02–05、PL01–06、SC04–05。先做运行中追问/队列、结构化澄清、可编辑计划和可配置指引；项目检索单独按关键词、语义索引、符号依赖分阶段验收。每项需说明支持的远端/本地范围，不能统称“项目理解已完成”。

**P2：补齐开发工具与扩展。** 对应 ED05、ED07–10、CT10–12、MD03、MD05–08。加入 MCP、搜索、用量统计、原生 Git 审查及附件等；外部连接需明确权限与授权。AI 编辑器禁止与不可调整 deny 保持不变。

**P3：按产品需要选择平台化能力。** 对应 EC01–07、PL07–08、CV06–08。云端、多代理、协作和企业能力需要独立产品决策，不能作为每次终端修复的隐含范围。

命令与对话展示、复杂时间线回滚以及 AI 使用 Vim 不列入此次对齐开发。纯比较不会触发构建或安装。

## MD04–MD06 交付记录（0.19.18 / build 183）

- **MD05**：AI 工具栏“用量”查看当前任务输入、输出、缓存读取、缓存写入、推理、已知小计、估算费用及最近 200 次请求。更早数据计入累计；继续历史任务保留用量，旧版没有记录的历史显示未知、不能用于假定免费；新会话或分叉重新统计。Claude 缓存补入总输入；推理包含在输出内，不重复计费。Codex 原生线程按累计用量差额计入，重复报告不重复增加；CLI 可能延迟报告或不提供用量，此时显示未完整提供，不推算为零。请求列表对应 Axon 的模型决策／续接，原生工具续接不等于另开一个收费回合。
- **预算边界**：设置可选每任务 Token / 估算美元限额，价格按当前后端和模型填写美元／百万 Token，并随预设保存；每次请求保存当时单价，改价不重算旧记录。达到限额后暂停下一次模型请求和工具操作；未知用量或未定价记录使预算无法核对时保守暂停。检查发生在响应边界，正在进行的响应可能超出限额，不能保证供应商账单硬上限；CLI 订阅、折扣和外部工具收费不由 Axon 推断。
- **MD06**：AI 设置添加最多 8 个服务，支持本机 stdio（绝对可执行文件、字面 JSON 参数、项目目录）和 Streamable HTTP（HTTPS；HTTP 仅本机）。保存不启动服务，手动连接后发现最多 64 个工具／4 页，逐个选取工具；凭据放 Keychain，stdio 仅注入指定环境变量，HTTP 用 Bearer。连接配置或工具目录改变后需重新连接。仅支持声明 readOnlyHint 且未命中危险名称、经用户选中的工具，按 Axon MCP 类别与逐服务权限审批，审批后再核对连接及权限。工具结果作为不可信数据显示，保留来源、错误状态和执行记录；传输失败不自动重发调用。
- **MCP 边界**：stdio 使用 macOS sandbox-exec，禁止写入、网络、信号及任意其他程序执行；读取限于系统运行库、项目与显式脚本目录，Python 启动所需根目录规则是 literal("/")，不是递归 subpath("/")；项目外合成文件读写验证均被拒绝。HTTP 的只读注解由服务提供，不能证明服务器没有副作用，因此只连接明确可信服务；Axon 不授予服务器额外账号权限。本批不支持任意写工具、OAuth、旧 SSE 传输、资源自动读取、sampling / elicitation 或服务主动执行请求。媒体内容不自动加载；模型进程仍不能继承 CLI MCP 绕开 Axon。
